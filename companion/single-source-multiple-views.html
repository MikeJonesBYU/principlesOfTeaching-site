CS 356 · Reading the Teaching Skills codebase

One Source, Many Views

The Teaching Skills site stores its 53 skills once and shows them five different ways. This tutorial shows how that is organized, then walks through adding a sixth way: a brand-new organizing scheme called the Ladder. Read the pictures first. The prose is deliberately short.

1The whole idea in one picture

One file holds the facts. Every page is a view that reads those facts and arranges them. Nothing about a skill is typed twice. The glue is a stable id on every skill.

2What is already here

Every skill is one object. Three fields are the manual's own organization. One field is the key. The rest is content.

Three kinds of view

Look at how each page gets its arrangement. There are only three moves in the whole site.

PageArranged byHowMove
structure.htmlprinciple → manual page → skillGroups skills on the subsection field at render time.derived
index.htmlone skill per principle, randomWalks sections[], picks one from each.derived
select.htmlone radio group per principleSame walk. Writes the chosen ids into the URL.selection
summary.htmlthe five ids in #sel=Builds an id → skill index, joins descriptions.js.selection + overlay
problems.html7 categories → 29 challenges → skillsWalks problems-data.js, looks up each id in the source.overlay
Derived = the field you group on is already in the source. No new file.
Overlay = a new file that lists ids under new headings. Adds meaning, never copies content.
Selection = a list of ids carried in the URL. The view is whatever those ids resolve to.

3Same 53 dots, regrouped

Each dot is one skill, colored by its principle. Switch the grouping. The dots never change; only the boxes around them do. That is the entire lesson.

4The new scheme: the Ladder

Every existing scheme asks what a skill is about. The Ladder asks how ready a teacher has to be to try it. A first-week volunteer and a ten-year veteran should not get the same list.

1
First SundaysDoable this week with no preparation and little risk. "Communicate that students are needed."
2
Building habitsNeeds preparation during the week. Becomes a routine. "Create open-ended search questions."
3
Reading the roomNeeds in-the-moment judgment or doctrinal care. "Respond without speculation."
4
Holding steadySustained charity under strain. "Testify of God's love when it is hard to feel it."

Decide the shape before touching a file

Four questions settle almost everything about the implementation. Answer them in a sentence each.

QuestionManual hierarchyProblems overlayThe LadderWhy it matters
How many places can one skill appear?exactly onemany (or none)exactly oneOne place means you can validate "every skill, once." Many means you validate "no bad ids."
Are the groups ordered?manual ordernoyes, 1 → 4Ordered groups get an order number and a "next rung" view for free.
Authored or derived?in the sourceauthoredauthoredAuthored means a new file. Derived means a few lines in a view.
Does the grouping carry language?yes, in each bundleyes (but English only)labels yes, structure noKeep the structure language-neutral. Put labels where the other labels live.

  4. Write the view. It is a join, then a loop.

    Two inputs, one output. The index is the same six lines every other view has. The loop follows the overlay's order, not the source's.

    assets/ladder.js  (new)(function () {
  function init() {
    var D = window.TDS_DATA, L = window.TDS_LADDER, t = window.TDS_I18N.t;
    var root = document.getElementById("ladder");
    if (!D || !L || !root) return;

    // 1. index the source by id — colour and section ride along from the source
    var SK = {};
    D.sections.forEach(function (s) {
      s.skills.forEach(function (k) {
        SK[k.id] = { name:k.name, url:k.url, gist:k.define, section:s.title, accent:s.accent };
      });
    });

    // 2. walk the overlay in its own order; labels come from strings
    var html = "";
    L.rungs.slice().sort(function (a, b) { return a.order - b.order; }).forEach(function (r) {
      html += '<section class="rung" id="rung-' + r.id + '">' +
              '<h2>' + esc(t("ladderRung_" + r.id + "_Title")) + '</h2>' +
              '<p>'  + esc(t("ladderRung_" + r.id + "_Blurb")) + '</p><ul>';
      r.skills.forEach(function (id) {
        var sk = SK[id]; if (!sk) return;             // unknown id: skip, don't crash
        html += '<li style="--a:' + sk.accent + '">' +
                '<a href="' + sk.url + '">' + esc(sk.name) + '</a>' +
                '<span class="tag">' + esc(sk.section) + '</span></li>';
      });
      html += '</ul></section>';
    });
    root.innerHTML = html;
  }
  if (window.__tdsReady) init(); else document.addEventListener("tds:ready", init);
})();

    Switch the URL to ?lang=spa and the whole page is Spanish. The overlay never noticed.

  5. Link it. One line.

    index.html — the subnav<a href="structure.html" data-i18n="navBrowseAll">Browse the full list of all skills →</a>

    The data-i18n attribute means the link text is one more strings key. The loader rewrites relative links to carry ?lang=, so the language follows the reader.

  6. Check the join. Every time you edit.

    An overlay can drift from its source. A one-to-one scheme has a stricter test than a many-to-many one. Paste this into the browser console on ladder.html.

    console check (or a 15-line Python script in tools/)var ids = [], all = new Set();
TDS_DATA.sections.forEach(s => s.skills.forEach(k => all.add(k.id)));
TDS_LADDER.rungs.forEach(r => ids.push(...r.skills));

console.log("unknown ids:",  ids.filter(i => !all.has(i)));                 // must be []
console.log("missing:",      [...all].filter(i => !ids.includes(i)));       // must be []  (one-to-one)
console.log("duplicates:",   ids.filter((i, n) => ids.indexOf(i) !== n));   // must be []  (one-to-one)

    For comparison, the same check on problems-data.js reports two skills missing. That is allowed there. It is a bug here.

A second view for free

Views compose. The summary page already carries five ids in #sel=. Read them on the Ladder page and you get "where your five skills sit, and what the next rung looks like" with no new data at all.

assets/ladder.js — optional addition// rung of each skill, inverted from the overlay
var rungOf = {};
L.rungs.forEach(function (r) { r.skills.forEach(function (id) { rungOf[id] = r.order; }); });

// the reader's five, from the same hash the summary page uses
var m = /sel=([^&]*)/.exec(location.hash);
var mine = m ? m[1].split(",") : [];
var highest = Math.max.apply(null, mine.map(function (id) { return rungOf[id] || 0; }));
// highlight `mine`, then suggest a skill from rung `highest + 1`

Once the join exists, counting is a view too. This matrix is the source crossed with the overlay. It shows the example assignment used on this page, and it is what a reviewer looks at first.

6Rules to carry to your own project

Ids are addresses. Give every record one. Never rename it. Views, overlays, URLs, and other languages all meet at the id.
Overlays point; they do not copy. If a name appears in two files, one of them is wrong.
Structure and words are separate. Slugs in the structure file. Labels in the strings file. Renaming a label is then a display change only.
Decide cardinality first. One place or many? Ordered or not? Those answers write your validator.
A new view touches no old view. If adding a page forces you to edit another page's script, the source has leaked into a view.

7Try it

  • Derived: group the 53 skills by the first verb of name ("Ask", "Create", "Invite", "Testify" …). No new file. Which move from §2 is this?
  • Overlay, many-to-many: tag skills by audience: children, youth, adults. Write the validator before the data. What does "missing" mean here?
  • Repair: move the category and challenge titles out of problems-data.js into the strings files. What breaks on the way? What now works in Spanish?
  • Compose: make problems.html show each helping skill's rung. Which file do you add a script tag to? Which file do you not touch?
